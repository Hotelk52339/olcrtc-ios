# AGENTS.md

The project-context file for olcrtc-ios: the rules that bind every change, how
to build and verify one, the full command set, and the architecture those rules
assume. The contribution process — pull requests and conventions — is in
[`CONTRIBUTING.md`](CONTRIBUTING.md), and this file points into it for detail. If
the two ever disagree, that is a bug — reconcile them. README.md holds the
user-facing docs, the connect / install flow diagrams, the server-side layout and
the srv.sh patching workflow (*How srv.sh works*).

olcrtc-ios is an iOS SOCKS5 proxy client that tunnels traffic over WebRTC
conferencing carriers. The Xcode project is **generated by XcodeGen** from
`project.yml` (the `.xcodeproj` is not authoritative and is not hand-edited); the
proxy core ships as a gomobile-built `App/Mobile.xcframework`.

Work reaches you as a numbered task. The number is permanent and load-bearing:
code carries `// #NNN` markers tying a changed line back to its task, because
commits are coarse-grained and several tasks often land in one. The tracker
itself is private and outside the repository; describe your change in the pull
request. The marker format is in CONTRIBUTING.md → *Marking task-driven changes*.

---

## 1. Golden rules

1. **Tag every task-driven change to its task.** When you implement a numbered
   task, leave an inline trail: annotate new or changed code with
   `// #NNN: <why>`, comment out replaced code as `// #NNN was: …` instead of
   deleting it, and wrap multi-line edits in `// boc #NNN` … `// eoc #NNN`.
   These comments — not the coarse git history — are the per-task change record
   the code carries. Full format and the "keep it proportionate" guidance:
   CONTRIBUTING.md → *Marking task-driven changes*.
2. **English everywhere** — code, comments, docs, identifiers, commit messages.
   Never hardcode user-facing strings: add an `L10n` case in
   `App/Localization/L10nTable.swift` (English is the source language, then
   localized). Details: CONTRIBUTING.md → *Language*.
3. **Conventional Commits** for messages: `<type>(<scope>): <imperative summary>`.
   CONTRIBUTING.md → *Commit messages*.
4. **Keep secrets out of code and logs** — `LogStore.redactSecrets()` redacts keys
   and URI key-segments.
5. **Keep changes small and idiomatic** — match the surrounding file, comment the
   *why* not the *what* (the markers in rule 1 are the deliberate exception), and
   don't add abstractions or error handling beyond what the change needs.

## 2. Build, test, generate

The full command set — one-time setup, running a single test, the checks that
need no Xcode — is under *Commands* below (including how to resolve `$UDID`).
The three that matter on every change:

```bash
xcodegen generate --spec project.yml   # after editing project.yml or adding source files
xcodebuild test -project olcrtc-ios.xcodeproj -scheme olcrtc-ios-tests -destination "id=$UDID"
python3 scripts/parity_check.py        # after touching scripts/srv.sh
```

- `olcrtc-ios.xcodeproj` and `App/Info.plist` are **generated** from `project.yml`
  — never hand-edit them; regenerate with `xcodegen`.
- `scripts/srv.sh` is a patched copy of upstream; keep all local changes inside
  `# boc olcrtc-ios` / `# eoc olcrtc-ios` markers, and carry deliberately-skipped
  upstream lines as commented copies inside `# boc olcrtc-ios-rejected: <reason>`
  blocks (#325) — `parity_check.py` fails the build on drift in either direction
  (our base lines must exist upstream; upstream lines must be adopted or
  rejected). CONTRIBUTING.md → *srv.sh parity*.

## 3. Versioning — one bump per build

`CFBundleVersion` (the **build number** in `project.yml`) is a single global
counter identifying a built artifact. It is bumped **once per build, by whoever
runs the build** — the maintainer integrating changes, not each contributor — so
concurrent work never races the counter. A change submitted for review does not
bump it.

- **`MARKETING_VERSION`** changes only on an explicit release decision — never
  automatically.
- **Doc, comment, or localization-string-only changes need no build-number bump**
  (and no build or test) — this file's own edits are an example.

---

## 4. Hard don'ts

- Don't hand-edit `Info.plist` or `olcrtc-ios.xcodeproj` (both generated).
- Don't bump `MARKETING_VERSION` unless explicitly asked, and don't bump the
  build number for a change you are submitting for review — the build owner does.
- Don't `git push` / publish to a remote — the maintainer always does the push.
- Don't rely on guidance (including this file) that contradicts the actual code or
  the symbols the framework exports. Verify a function or flag exists before
  building on it — e.g. check the gomobile header at
  `App/Mobile.xcframework/ios-arm64/Mobile.framework/Headers/Mobile.objc.h`.

## Commands

Building and testing need macOS with the full Xcode 15+ (iOS 17 SDK).
`olcrtc-ios.xcodeproj` and `App/Mobile.xcframework` are gitignored — regenerate /
fetch them before any `xcodebuild`. Any local `xcodebuild` (build *or* test) also
needs the `olcrtc-upstream` submodule: the parity pre-build phase exits 1 without it.

```bash
# One-time setup
git submodule update --init --recursive     # olcrtc-upstream/ (submodule `olcrtc`, tracks master): Go core + upstream srv.sh
./scripts/fetch-framework.sh [vTAG]         # prebuilt Mobile.xcframework from a GitHub Release (needs `gh auth login`)
./scripts/build-framework.sh                # …or `gomobile bind` it from olcrtc-upstream/mobile (needs Go, ~5 min); redo only when the pin moves
xcodegen generate --spec project.yml        # writes olcrtc-ios.xcodeproj + App/Info.plist; rerun after editing project.yml or adding files

# Tests (simulator names drift between Xcode versions — pick whatever iPhone is installed)
UDID=$(xcrun simctl list devices available | grep -m1 'iPhone' | grep -oE '[0-9A-Fa-f-]{36}')
xcodebuild test -project olcrtc-ios.xcodeproj -scheme olcrtc-ios-tests -destination "id=$UDID"
xcodebuild test ... -only-testing:olcrtc-ios-tests/TunnelManagerStateTests              # one class (class name, not file name)
xcodebuild test ... -only-testing:olcrtc-ios-tests/TunnelManagerStateTests/testMethod   # one test

# App build only
xcodebuild build -project olcrtc-ios.xcodeproj -scheme olcrtc-ios -destination "id=$UDID"

# Checks that run without Xcode
python3 scripts/parity_check.py             # srv.sh vs upstream; also the app target's pre-build phase (every build, incl. tests) and CI's first step
python3 scripts/parity_check.py --selftest  # in-memory self-test, no submodule needed
python3 scripts/test_olcrtc_bot.py          # unittest for the server-side control bot (stdlib only; not in the Xcode target, not run by CI)
swiftlint                                   # .swiftlint.yml is deliberately lenient; CI runs it non-strict

# Artifacts / release (maintainer)
./scripts/package-ipa.sh                    # unsigned .ipa for sideloading (release.yml does this per v* tag)
python3 scripts/cut-release.py --dry-run    # tag v<MARKETING_VERSION>.<CFBundleVersion> from the private backlog/ ledger
```

- `App/Info.plist` is generated **and tracked**: after `xcodegen generate` following a
  `project.yml` change (build number, plist keys), commit the regenerated diff.
- On Windows the full `parity_check.py` run needs `PYTHONUTF8=1` (srv.sh line 3 is
  Cyrillic and the script opens files with the platform encoding; `--selftest` never
  opens a file).

## Architecture

### The three "olcrtc" pieces

- `olcrtc-upstream/` — git submodule with the Go core and upstream `script/srv.sh`;
  used only at build time (framework build from `./mobile`, parity check).
- `App/Mobile.xcframework` — that core compiled with gomobile, now bound TOGETHER
  with the local `gomobile/tunstack` tun2socks glue (#vpn) in ONE framework that
  serves both the app and the packet-tunnel appex; the only binary that ships. Two
  files import `Mobile`: `App/Core/TunnelEngine.swift` (proxy mode) and
  `Tunnel/PacketTunnelProvider.swift` (VPN mode).
- This repo — the SwiftUI app (`App/`), its tests (`Tests/`), and the server-side
  scripts it uploads over SSH (`scripts/srv.sh`, `rotate-key.sh`, `olcrtc-bot.py`,
  bundled as app resources via `project.yml`; a script missing from that list still
  works on simulator through the `#filePath` fallback and fails only on device).

### Composition root, ownership, threading

- `OlcrtcApp` is a bare `WindowGroup { MainTabView() }`. `MainTabView` (`App/App.swift`)
  creates the app-wide stores (`ConnectionStore`, `TunnelManager`, `IPChecker`,
  `SpeedTest`, `ServerHostStore`, `BotStore`, `LogsRouter`, `UpdateChecker`) as
  `@StateObject`s and passes them down **by initializer** (children hold
  `@ObservedObject`). No `.environmentObject` anywhere; a new app-wide store means a
  new `@StateObject` on MainTabView threaded through initializers. `Provisioner` is
  the per-tab exception: ServersView and LogsView each own their own instance.
- Directly reachable singletons: `SettingsStore.shared` (deliberately **not**
  `@MainActor` so nonisolated code can read it; UserDefaults-backed, persists on a
  serial queue) and `LogStore.shared` (`@MainActor`). `ConnectionStore.shared` /
  `TunnelManager.shared` are *weak, last-init-wins* statics that exist only for App
  Intents (`App/TunnelAppIntents.swift`) — never use them as view wiring.
- MainTabView also owns the cross-cutting behaviour: `onOpenURL` dispatch for
  `olcrtc://` (plain connection, or full-access `olcrtc://host/v1/<base64url>`) and
  `olcrtc-sub://` links; scenePhase (`.active`: `store.rehydrateSecrets()` +
  `tunnel.noteForeground()`; `.background`: `tunnel.noteBackground()` +
  `LogStore.shared.flush()`); auto-connect on launch; the update check and
  subscription refresh. Tabs are hardcoded ints 0–4 and `LogsRouter` forces
  `selectedTab = 3` for Manage VPS → Logs.
- Every `ObservableObject` store and `BackgroundRuntimeKeeper` is `@MainActor`
  (SettingsStore excepted). Stateless services are nonisolated `enum`s of statics
  (`SOCKSSession`, `NetPing`, `SSHRunner`, `SubscriptionFetcher`, `PortAvailability`,
  …); `OlcrtcEngine` and `LogFileWriter` are nonisolated classes guarding their own
  state (the Go singleton / a serial `ioQueue`). `Task.detached` is used only for the
  engine paths: `runEngine` (`engine.start` then the `verifyTunnel` probes), the
  off-actor `engine.stop()` in `disconnect()`, and `MobilePing` / `MobileCheck`.
  Values crossing into those tasks are snapshotted on MainActor first
  (`EngineStartSettings`, `EngineProbeSettings`) — never read `SettingsStore` from
  engine code. Off-actor readers use lock-backed statics (`TunnelManager.liveBoundPort`,
  `lastTunnelActivityDate`), not `nonisolated(unsafe)`.

### Tunnel state machine (`App/Core/TunnelManager.swift`)

- `ConnectionState`: `disconnected | connecting | connected | waitingForNetwork |
  failed(String)`. `state.didSet` (guarded by `state != oldValue`) centralises the
  per-state side effects: transition log line, keep-alive start/stop,
  `BackgroundRuntimeKeeper` start/stop, wedge reset + exit-geo log on `.connected`,
  and `boundPort` clearing on `.waitingForNetwork` / `.disconnected` / `.failed`
  (never on `.connecting`, which preflight sets just before). `disconnect()` still
  cancels its tasks and stops the engine itself before setting `.disconnected`.
- `connect(record:)` → `start` → `preflight`, which on the normal path runs
  **synchronously** on MainActor (validate → reserve the configured SOCKS port →
  `boundPort = port` → `connectEpoch &+= 1` → `.connecting`), then
  `Task.detached { runEngine }`. Every detached continuation may publish only through
  `isLiveAttempt(epoch)` — that is what makes fast disconnect→reconnect safe. The
  core's "ready" is not enough: `verifyTunnel` races HTTPS probes through the SOCKS
  port and only an HTTP 200 publishes `.connected`.
- Three triggers converge on one idempotent `requestReconnect(reason:)`: keep-alive
  (3 consecutive verify misses), `NWPathMonitor` (regain / interface swap, decided by
  the pure `pathDecision`), and the opt-in `WedgeDetector` (core log signatures).
  Backoff 2·2ⁿ s capped at 60 s minus up to 25 % jitter, 6 attempts, then
  `.failed(reconnectGaveUp)` (OLC-1014). It is a no-op unless `lastRecord != nil`
  and no loop is running — `disconnect()` nils `lastRecord`, so nothing auto-reconnects
  after a user disconnect. A manual `connect()` never enters the loop; only the loop
  passes `isReconnect: true`, which triggers the carrier rejoin-settle sleep in
  `OlcrtcEngine.start`.
- Port policy (#308): the configured port is bound exactly or the attempt fails with
  the port-busy reason (OLC-1026 from the preflight `isFree` check; the same message
  without a code when the Go bind races) — never slide to another port. Sole
  exception: a user/intent `disconnect()` released that same port ≤10 s ago, in which
  case `start` flips `.connecting` first and polls the port (250 ms, ≤5 s) inside the
  cancellable `pendingStartTask` before running preflight.
- `connectedRecord` — not `store.primary` — says which node is live; tapping a row
  changes `primary` without reconnecting.
- Protocol seam: `ConnectionDetails.engine` (TunnelEngine.swift) is the only mapping
  from a details case to an engine. A new protocol = new `ConnectionDetails` case +
  new `TunnelEngine` conformer. The state machine is protocol-agnostic, but two
  olcrtc-specific helpers still sit on `TunnelManager` (`validate(params:)`, called
  back by `OlcrtcEngine.validate`, and `recordForBatchPing`) and would need relocating.
- Dual backend (#vpn): `connect(record:)` reads `SettingsStore.tunnelMode` once and
  routes to the in-app proxy (`start` → the OlcrtcEngine path above) or the system
  VPN (`startVPN` → `VPNController`). `private(set) var activeMode` records which.
  **Every in-app-proxy side-effect — `state.didSet` `.connected` (keep-alive, wedge
  reset, exit-geo, background-audio keeper) and `handlePathUpdate` — is gated on
  `activeMode == .proxy`**; in VPN mode the core runs in the appex and `NEVPNStatus`
  is the truth. `vpnStatusChanged` (via the `vpn.$status` sink) mirrors it back
  through the pure `connectionState(forVPNStatus:hasRecord:reason:)`. A live session
  never switches backend (the mode picker disables unless `.disconnected`).

### System-VPN mode (`App/Core/VPNController.swift`, `Tunnel/`, `gomobile/`)

- The opt-in whole-device tunnel. `VPNController` (@MainActor) drives one
  `NETunnelProviderManager`: reuse-or-create → `NETunnelProviderProtocol`
  (`providerBundleIdentifier` = the appex, non-nil `serverAddress`,
  `providerConfiguration` from `VPNConfig`) → `saveToPreferences` → **mandatory**
  `loadFromPreferences` → observe `.NEVPNStatusDidChange` → `startVPNTunnel`. The
  first `saveToPreferences` is the runtime capability gate: a free-Apple-ID sideload
  strips the Network-Extension entitlement, the save fails (`NEConfigurationErrorDomain`
  10 / `NEVPNErrorDomain` 5), `capability` flips to `.unavailable`, and the Config tab
  greys out the VPN chip → proxy-only. `probeCapability` is the lazy, side-effect-free
  pre-check (a bare `loadAllFromPreferences` never pops the consent alert).
- `Tunnel/PacketTunnelProvider.swift` — the `NEPacketTunnelProvider` appex
  (`NSExtensionPrincipalClass` = `$(PRODUCT_MODULE_NAME).PacketTunnelProvider`). It
  configures its OWN `MobileRuntime` with the SAME setter sequence as `OlcrtcEngine`,
  binds a loopback SOCKS listener with NO credentials (the core accepts NO-AUTH on a
  loopback bind — upstream `session/validate.go`), then pumps IP packets through
  `gomobile/tunstack` (Outline-SDK `lwip2transport` + `dnstruncate`, TCP-CONNECT
  only). It rejects `videochannel` (an appex has no UI process for the WebView codec)
  and tunes the Go runtime for the ~50 MB NE jetsam cap (`MobileTuneForNetworkExtension`
  / `MobileSetMuxBuffers` / `MobileFreeOSMemory`). No App Group: config rides
  `providerConfiguration`, logs/stats come back via `handleAppMessage`.
- Build: `scripts/build-framework.sh` binds the upstream `mobile` package AND
  `./tunstack` from the `gomobile/` wrapper module in ONE `gomobile bind` (two
  gomobile frameworks can't co-link — duplicate Go runtimes). Four build-time shims
  (`scripts/mobile-shim/*.go`) are copied into the submodule for the bind and
  trap-removed so it stays clean: `logbridge` re-adds the master-removed
  `SetLogWriter`, `memory` exports the NE knobs, `protect_utun` appends `utun`/`ipsec`
  to pion's ICE interface filter, `smuxlimits` re-declares the two smux buffer consts
  as vars + a setter (its ONE patch: `build-framework.sh` grep-anchor-deletes those
  const lines from `internal/runtime/runtime.go`). CI runs `go test ./tunstack` on
  every build — the packet path never runs in the simulator, so that compile is its
  only gate. The Xcode project builds TWO targets (`olcrtc-ios` + the embedded
  `olcrtc-tunnel` appex).

### Data model and persistence

- `ConnectionRecord` (envelope: id, name, group, subscription provenance) →
  `ConnectionDetails` (Codable enum, today only `.olcrtc(OlcrtcConnection)`;
  synthesized encoding, so the on-disk JSON is `{"olcrtc":{"_0":{…}}}`) →
  `OlcrtcConnection` (engine-start parameters: core fields go to
  `MobileStartWithTransport`, vp8 / wbToken through `MobileSet*` setters; the `sei*`
  fields are server-side only and never reach the engine). `OlcrtcURI.Parsed` is
  transient; the blessed mapping is
  `OlcrtcConnection.init(from: OlcrtcURI.Parsed, clientID:socksUser:socksPass:)` —
  only `ServersView`'s reconfigure (keeps old key/vp8/sei/socks) and recover
  (maps `SSHRunner.RecoveredConfig`) build one by hand.
- Secrets never reach UserDefaults, enforced twice: `OlcrtcConnection.CodingKeys`
  omit `key` / `socksPass` / `wbToken`, and `ConnectionStore.save()` (fired by
  `connections.didSet`) upserts non-empty ones into the Keychain via
  `ConnectionSecretStore` and blanks them before encoding. `save()` never deletes a
  Keychain item for a secret cleared to "" — only `remove` / subscription removal do,
  so a blanked secret resurrects on the next launch. `load()` re-hydrates from the
  Keychain; a read error on the *key* (device locked before first unlock) sets
  `secretsLocked`, which `TunnelManager.connect` consults through an injected closure.
- Sibling stores use the same split: `ServerHostStore` (`olcrtc_server_hosts` +
  Keychain `olcrtc.serverhost.password`), `BotStore` (`olcrtc_bots` +
  `olcrtc.bot.token`), `SettingsStore.localSocksPass` (`olcrtc.local.socks`).
  All `settings.*` keys live in `SettingsStore.Keys`; numeric settings clamp in
  `didSet` (and on read in `init`) to the ranges in `SettingsStore.Defaults`
  (`fontSizeIndex` clamps to `fontSizes`). Adding a setting touches Defaults, the
  property, init, `reset()`, Keys — and the `SettingsStoreTests` snapshot.
- The record stores (`olcrtc_records_v2`, `olcrtc_sub_meta_v1`, hosts, bots) have no
  migration code: evolution is `decodeIfPresent` only, and a decode failure of
  `olcrtc_records_v2` re-saves an empty list. Adding a `ConnectionDetails` case is
  therefore not downgrade-safe. The one migration in the codebase is
  `SettingsStore.init` mapping the legacy Bool `settings.debugLogging` to `logLevel`.
- Subscriptions: `ConnectionStore.diffSubscription` keys nodes by
  (source link, `Entry.nodeKey` = carrier·transport·room·key·clientID) and produces
  add / update-in-place / remove. Manual `add()` has no dedup, and
  `AddConnectionView.save()` rebuilds the record without `sub*` provenance or
  `wbToken` — an edited subscription record duplicates on the next re-import.

### VPS provisioning over SSH

- Layers: `Provisioner` (`@MainActor`, publishes `status`, 5 s TCP pre-probe before
  every SSH op; it does not serialize itself — `ServersView.run` / `actionsDisabled`
  enforce one op at a time, and LogsView's own instance can overlap it) →
  `SSHRunner` (nonisolated `enum` of static script builders and pure output parsers
  plus the Citadel primitives `_withConnection` / `_execute`; `installEnv` reads
  `SettingsStore.shared` for DNS and the vp8 sliders) → `SSHClientProtocol` (single
  `execute(command:)`; `CitadelSSHClient` in production, `Tests/Mocks/MockSSHClient`
  in tests), used only by the injectable `pollLoop`.
- The server contract is plain text. Most scripts emit `KEY=VALUE` lines
  (`OLCRTC_URI=`, `OLCRTC_CONTAINER=`, `OLCRTC_UNINSTALLED=ok`, readiness `PODMAN=` /
  `IMAGE=` / `CONTAINER=` …) read by `SSHRunner.extract` / `parse*`; the exceptions
  are the tab-separated container scan, recover-config's sentinel-bracketed YAML
  dump, the `OLCRTC_BOT_BEGIN/END` blocks and raw `podman ps` / `podman logs` output.
  Only bot-deploy reports recoverable preconditions as `OLCRTC_BOT_ERROR=<reason>`
  with exit 0; every other script fails with `exit 1` + an `ERROR:` line, which
  reaches the UI through `_execute`'s stderr merge as `ProvisionError.sshCommand`.
  Arbitrary text (scripts, bot config) travels base64; user-supplied strings
  (carrier, transport, room, jitsi URL, token, bot marker) go through `shellSafe`
  (an allow-list strip, not quoting); container names are trusted script output.
- `SSHRunner.installEnv()` → `OLCRTC_*` env vars → `scripts/srv.sh` (`# boc olcrtc-ios`
  patches). `ServerScriptParityTests.testEnvVarNamesMatchSrvShBocPatches` greps those
  blocks for `$OLCRTC_*` reads and requires each to be emitted by `installEnv` (for
  telemost/datachannel, jitsi/datachannel, wbstream/vp8channel) or listed in its
  local `scriptDefaults` allow-list; `scripts/parity_check.py` keeps srv.sh itself
  aligned with upstream. `reconfigureScript` consumes only carrier / transport /
  room ID — vp8, sei, jitsi URL and wbToken never reach `server.yaml` on reconfigure.
- Post-install ops never hard-code the deploy dir: they resolve it via `podman
  inspect`; reconfigure and `rotate-key.sh` edit `server.yaml` + `podman restart`,
  recover only reads it, start runs `podman start`, update rebuilds in-container +
  restart — never `podman run` / `rm` (`RotateKeyScriptTests` and
  `SSHRunnerRecoverConfigTests` assert this for their scripts). `RotateKeyScriptTests`
  also requires every non-comment line inside `rotate-key.sh`'s `# boc srv.sh` blocks
  to exist verbatim in srv.sh (a line-set check with a >80-line floor).
- Multi-carrier (#452): one VPS can run several protocols at once. The primary
  install is unchanged; `scripts/add-carrier.sh` (bundled like rotate-key.sh)
  attaches `server-<carrier>.yaml` + a sibling container `<base>-<carrier>` to
  the SAME deploy dir (shared binary + shared key, no rebuild, ~seconds) —
  `SSHRunner.addCarrier` runs it synchronously, no nohup/poll. The host card's
  per-protocol rows come from `carrierListScript`/`parseCarrierList`
  (OLCRTC_CARRIER_BEGIN/END blocks; container derived from the yaml name);
  `removeCarrierScript` deletes a sibling (never the primary),
  `recoverConfigScript(configFile:)` reads a sibling's yaml, and rotate-key.sh
  re-keys every `server-*.yaml` + restarts `<base>-*`, reporting
  `OLCRTC_SIBLING_URI=<container>|<uri>` per sibling (split on the FIRST `|`).
  Sibling ops (add/remove/start/stop) run OUTSIDE `run()`/HostDisplay —
  the card base tracks only the primary container. Sibling records live in
  `ServerHost.extraConnectionIDs`; multi-installs name records
  "<label> · <Carrier>" (`ServersView.recordName`).
- The VPS card state is the pure reducer `HostDisplay` (`App/Models`): the base comes
  from a readiness probe when the op returns one, else `HostOp.target`, else the
  previous base (`terminalBase`); `ServersView.run` drives start/terminal
  transitions, `advancePhase` / `retry` / `restoreContainer` are the other writers.

### Logging and diagnostics

- `LogStore.log()` pipeline: level gate (`.off` drops everything; below `.verbose`
  drops Pion noise — there is no other level filtering) → `redactSecrets` (64-hex
  keys, URI `#key`, `pass`/`passwd`/`password` `=`/`:` values, `OLCRTC_WB_TOKEN=`,
  YAML `token:`) → `[OLC-####]` prefix from `OlcCode` → keyword severity
  classification (an explicit `level:` bypasses it) → bounded buffer → file (only if
  a `startSession` created a writer) → coalesced `revision` bump (≤4/s).
  `logContainer(serverPrefix:)` is a separate pipeline (only the `.off` gate, no
  code prefix, parses `Current peers count`).
- `entries` / `containerEntries` are deliberately **not** `@Published` — views must
  observe `$revision`. Only four operation kinds open a `startSession`: each
  connect / reconnect attempt (`preflight`), each provisioning op, IP check, speed
  test; everything else (imports, health check, port check, store CRUD) logs into
  `.connection` and stays memory-only until the first connect creates that writer.
  Files are fixed per category / per host and rotate (2 MiB → newest 1 MiB) only at
  `startSession`.
- Container (podman) logs are per host, keyed by `ServerHost.logFilePrefix`: use
  `logContainer(serverPrefix:)`, never `log(.containerLogs, …)` (a dead bucket).
- Go-core lines arrive via `MobileSetLogWriter` in `OlcrtcEngine.init`, hop to
  MainActor into `.connection`, and also feed `OlcrtcEngine.coreLineObserver`
  (the WedgeDetector hook).
- Diagnostics (IPChecker, SpeedTest, `verifyTunnel`, exit geo) build their sessions
  with `SOCKSSession.make(mode:)`; `.tunnel` sets `connectionProxyDictionary` with
  literal string keys (`SOCKSEnable` / `SOCKSProxy` / `SOCKSPort` =
  `TunnelManager.activeSocksPort`, which prefers the live bound port). Successful
  tunnel transfers call `SOCKSSession.noteTunnelActivity()` (SpeedTest reserves
  180 s up front); keep-alive skips its probe on every tick within one interval of
  that marker.

### Localization

- No `Localizable.strings`: `L10n` (String-raw `CaseIterable` enum) +
  `L10nTable.english` / `.russian` dictionary literals; the language is the app
  setting `settings.language` (seeded once from `Locale.preferredLanguages` — ru →
  "ru", else "en"; never consulted again at lookup time). Adding a string = add the
  case (suffix `_fmt` with `%@` / `%d` / `%.0f` when it takes arguments) + an entry in
  **both** dictionaries (write `ru = en` explicitly when identical). `L10nTests` fails
  on any missing key or count mismatch (its placeholder check is currently vacuous —
  it filters on `Fmt`, the cases end in `_fmt` — so check `%` slots yourself), and a
  duplicate key inside a dictionary literal traps at first use.
- Call `L10n.x.localized()` / `.formatted(args)` at the point of use (inside `body`,
  at log-emit time) — never cache in a `let` / `@State` / static. Persisted tokens
  stay locale-stable: `ConnectionRecord.defaultGroupName == "Servers"` is displayed
  via `L10n.groupDefault` ("Connections") and `AddConnectionView.save()` maps the
  localized label back to the token (the one deliberate cached-`@State` exception).
- Sanctioned exceptions: `NSCameraUsageDescription` in
  `App/{en,ru}.lproj/InfoPlist.strings` (read by the OS; the English value must
  mirror `project.yml`), every OS-registered string in `TunnelAppIntents.swift`
  (intent titles, phrases, error), and `AppLocale.displayName`. `LogLevel.label`
  (SettingsStore.swift) is an *undocumented* English-only picker string — localize
  it if touched.

### UI conventions

- Screens compose the `Olc*` family in `App/UI/DesignSystem.swift` with
  `Theme.Palette` / `Metrics` / `Typography` tokens — no raw `.orange` / hex in views,
  no `@Environment(\.colorScheme)` branching. Light/dark (and Gray) pairs are tokens
  built inside Theme.swift with its *fileprivate* `dynamic(dark:light:)` / `isGray`
  helpers — add a token there rather than branching in a view. Typography maps to
  Dynamic Type styles so the root font slider scales everything.
- Sheets: ConnectionsView presents through one `.sheet(item:)` driven by the
  `ConnectionSheet` enum with a value snapshot (#330 — stacked `.sheet`s hung when
  editing the connected record under a live tunnel); ServersView / SettingsView still
  stack one `.sheet(item:)` per payload type. Follow the #330 pattern for any view
  that re-renders while a tunnel is live. Editor sheets are `NavigationStack { Form }`
  + `.olcSheet(confirm:)`, and `onConfirm` dismisses itself.
- Errors and results: ServersView / LogsView use `@State alertText: String?` + one
  OK alert titled `L10n.okPrompt`; destructive VPS ops use
  `.confirmationDialog(presenting:)`. Core code throws; views format with
  `L10n.stateErrorPrefix_fmt`.
- Don't derive collections in `body` on hot views (ConnectionsView re-evaluates
  ~10×/s during a speed test) — cache in `@State` via `.onChange(initial: true)`.
  Per-view loops live in `.task {}` and sleep-and-recheck instead of returning when
  a setting is disabled (an id-less `.task` never restarts).

### Testing conventions

- Tests run **inside the app process** (`TEST_HOST`), `@testable import olcrtc_ios`,
  against the real `UserDefaults.standard` and Keychain. Snapshot / restore every key
  you touch in setUp / tearDown, `ConnectionSecretStore.remove(connectionID:)` each
  UUID you create, restore `SettingsStore.shared` / `LogStore.shared` mutations, and
  call `SettingsStore.flushPendingWrites()` before asserting on UserDefaults
  (persistence is asynchronous).
- Testability pattern: decisions live in pure `static func` helpers on the owning
  type (`nonisolated` when the owner is `@MainActor`, e.g. `TunnelManager.pathDecision`;
  `LogStore.redactSecrets` is still MainActor-isolated; `SSHRunner.parse*` /
  `HostDisplay` are plain enums) with a thin side-effect layer; async / native paths
  are declared integration-only in the test file headers. Injection seams:
  `TunnelManager(secretsLocked:)`,
  `SSHRunner.pollLoop(sshClient:host:onStep:maxPolls:pollInterval:sleepFn:probeFn:)`
  (`MockSSHClient` answers strictly in order and throws when exhausted),
  `ConnectionStore.refreshDueSources(now:fetch:)`, injected `now` / `random` values.
- Lock `SettingsStore.shared.language = "en"` (and restore it) or compare against
  `L10n.x.localized()` — the default language follows the simulator locale.
- Every `TunnelManager()` overwrites the weak `.shared` and
  `OlcrtcEngine.coreLineObserver`; drive it back to `.disconnected` and reset the
  lock-backed statics. `connect()` with valid params launches a real engine task that
  fails asynchronously in the test host.
- `ServerScriptParityTests` / `RotateKeyScriptTests` read the **bundled** copy of
  `scripts/*.sh` first (source-tree fallback only when the resource is missing) —
  rebuild after editing a script. Test file names are historical: `OlcrtcURITests`
  lives in `ServerScriptParityTests.swift`, `TunnelManagerTests.swift` defines
  `TunnelManagerValidationTests`; `-only-testing:` takes the class name.
